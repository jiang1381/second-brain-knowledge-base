# 🧠 第二大脑（Personal Second Brain）

把自己的笔记灌进来，用自然语言提问，**答案带引用、带相关度**。
这是一个比普通 RAG 更完整的版本：**混合检索（向量 + BM25）→ 重排 → 引用溯源 → 置信度判断**。

> 技术路线：Python 标准库 + numpy，零重型依赖。核心检索逻辑全部手写。

---

## ✨ 功能

- 📂 **多格式笔记导入**：`.md` / `.txt` / `.html` / `.docx`
- 🔍 **混合检索**：向量（语义）+ BM25（关键词）双路召回，权重可调
- 🎯 **重排**：按「查询词覆盖率 + 标题命中」精排
- 📎 **引用溯源**：回答用 `[n]` 标注，并展示每条引用的相关度
- 🛡️ **反幻觉**：资料不足时明确说「没有」，不编造
- 💾 **笔记管理**：Web 端增删笔记、重建索引
- 🖥️ **Web + CLI** 两种用法

## 🔬 RAG 的四个进阶设计（面试重点）

### 1. 混合检索：向量 + BM25

单靠向量检索，遇到**专有名词、缩写、精确关键词**会吃亏；单靠关键词，又不懂同义表达。
所以两路同时召回再融合：

```
final = α × 向量分数 + (1-α) × BM25 分数
```

`α` 可在 `.env` 的 `ALPHA` 里调，Web 端也能切换「语义优先 / 混合 / 关键词优先」。

### 2. 重排（rerank）

粗召回 `3×top_k` 个候选后，再加两个信号精排：

```
final = 混合分数 + 0.20 × 查询词覆盖率 + 0.10 × 标题命中
```

### 3. 引用溯源

- prompt 里给每个片段编号 `[1][2]`，要求模型引用；
- 回答后用正则解析 `[n]`，只展示**真正被引用**的片段；
- 前端展示每条片段的三项分数（向量 / BM25 / 最终）。

### 4. 置信度与反幻觉

- 检索最高分低于 `MIN_SCORE` → 直接返回「没找到」，不调用大模型；
- 回答里没有任何 `[n]` 引用 → 标记「置信度较低」；
- 系统提示词明确：资料不足就说不知道。

## 🎯 面试时怎么讲

**一句话**："我做了个第二大脑，把笔记灌进去就能用自然语言提问，答案带引用。"

**讲检索**：
> "我不是只做向量检索，而是**向量 + BM25 混合**。向量负责语义，BM25 负责精确关键词，
> 用一个 α 加权融合，再对粗召回结果做重排（查询词覆盖率 + 标题命中）。
> 每个结果都有三项分数，是可解释的。"

**讲反幻觉**：
> "最高相关度低于阈值时直接返回'没找到'，不调模型；回答里没有引用也标为低置信度。
> 我宁可它说不知道，也不要它编。"

**讲工程**：
> "零重型依赖，API 调用是 urllib 手写的；索引在启动时重建，笔记改动后一键 reindex。"

**被问"怎么证明有效"**：
> "可以构造一组带标准答案的问题，算 Hit@k。我前面的项目就做过这个评测。"
